CS190 GUI 텍스트 편집기 과제에서 텍스트를 저장하는 클래스의 인터페이스를 둘러싼 사례다. 많은 팀이 backspace, deleteForward, deleteSelection 같은 화면 동작을 그대로 메서드로 만들어 얕은 메서드와 정보 누수를 낳았다. 글자를 넣고 범위를 지우고 위치를 옮기는 기본 연산만 제공하는 어느 정도 범용 API로 바꾸면 메서드 셋이 하나로 줄고 화면 코드가 오히려 더 뻔해진다.

## 강의에서

- **[[소프트웨어설계 06강 범용 모듈이 더 깊다|6강]]** — 화면 동작을 텍스트 클래스의 메서드로 만든 설계와 범용 기본 연산 설계를 견준다.
- **[[소프트웨어설계 07강 다른 층, 다른 추상|7강]]** — 문서 클래스가 텍스트 영역의 같은 이름 메서드를 그대로 부르는 통과 메서드의 예가 나왔다.
- **[[소프트웨어설계 08강 복잡성을 아래로 끌어내려라|8강]]** — 줄 단위 인터페이스는 구현을 단순하게 하는 대신 복잡성을 화면 쪽으로 올려 보냈다.
- **[[소프트웨어설계 11강 두 번 설계하라|11강]]** — 세 인터페이스를 화면 코드 입장에서 굴려 견준다.
